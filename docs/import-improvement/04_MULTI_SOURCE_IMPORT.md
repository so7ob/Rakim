# استيراد TXT وPDF لتشريع واحد

## القرار

تظل نسخة النص هي مصدر الاستخراج الوحيد في عملية الاستيراد. ويمكن إرفاق نسخة
PDF رسمية اختيارية للمقارنة البشرية وللتنزيل العام. لا تُستخرج مجموعة مواد
ثانية من PDF ولا تُنشأ مسودة تشريع ثانية.

## نموذج البيانات

- `source_imports.source_document_id`: مصدر الاستخراج الأساسي.
- `source_import_attachments`: مرفقات عملية الاستيراد قبل إنشاء التشريع، ودور
  PDF الحالي هو `OFFICIAL_PDF`.
- `legislation_source_documents`: مصادر التشريع بعد إنشاء المسودة، بأدوار
  `EXTRACTION` و`OFFICIAL_PDF` و`SUPPORTING`.
- رحّلت migration `1700000000014` مصادر النسخ القانونية الحالية إلى دور
  `EXTRACTION` للمحافظة على التوافق.

## API والتدفق

يقبل `POST /api/v1/imports` حقلي multipart:

- `file`: ملف الاستخراج الإلزامي، ومتوافق مع الصيغ المدعومة سابقًا.
- `referencePdf`: نسخة PDF الرسمية الاختيارية.

تُحسب بصمة مستقلة لكل ملف ويُتحقق من الحجم والتوقيع والامتداد قبل التخزين.
يدخل `file` فقط إلى مهمة `IMPORT_SOURCE`. تعرض شاشة المراجعة النص المستخرج
مقابل PDF المرفق، وعند اعتماد المراجعة تُعتمد وثيقتا المصدر معًا. عند إنشاء
المسودة تُنسخ علاقات المصدرين إلى `legislation_source_documents` داخل
transaction إنشاء المسودة نفسها.

يحمي `GET /api/v1/imports/:id/attachments/:sourceDocumentId` الملف المرفق
بصلاحية `source.view` ويتحقق من أن الوثيقة تتبع عملية الاستيراد المطلوبة.

عند تنزيل تشريع منشور، يختار `GET /api/v1/legislations/:id/source` المصدر
المراجع ذا الدور `OFFICIAL_PDF` أولًا، ثم يرجع إلى مصدر الاستخراج للتشريعات
القديمة التي لا تملك PDF.

`ÙØ§ÙÙÙ`. تُعاد محاولة decoding فقط عند وجود مؤشرات mojibake المعروفة،
ولا يُستبدل الاسم إذا نتج حرف Unicode غير صالح. يُخزن الاسم المصحح في MariaDB
ويستخدم في الواجهة وترويسة التنزيل RFC 5987.

## التدقيق والصلاحيات

لم تُنشأ صلاحية موازية: الرفع المتعدد محمي بالصلاحية القانونية القائمة
`source.upload`، والمعاينة محمية بـ`source.view`، والمراجعة بـ`source.review`.
يسجل Audit الرفع الأساسي وبيانات PDF المختصرة (الاسم والحجم والبصمة والنوع)
دون تخزين محتوى الملفات.
