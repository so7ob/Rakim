# دليل إدارة المحتوى والنظام

## الدخول والأدوار

الدخول من `/ar/login`. ينشئ `npm run seed` حسابات التطوير: `reader` و`data_entry` و`legal_reviewer` و`content_manager` و`system_admin` بكلمة المرور المحلية `DevOnly!ChangeMe2026`. لا تستخدم هذه الحسابات في الإنتاج.

| الدور        | المهام المسموحة                                                      |
| ------------ | -------------------------------------------------------------------- |
| قارئ/باحث    | البحث، المفضلة، البحوث المحفوظة، الملاحظات الخاصة والبلاغات          |
| مدخل بيانات  | رفع المصدر، إنشاء المسودة، تحرير بياناتها وموادها، وإرسالها للمراجعة |
| مراجع قانوني | مراجعة المصدر والمسودة، القبول أو الإرجاع، ومراجعة مشروع التعديل     |
| مدير محتوى   | النشر والأرشفة والقواميس ومعالجة الجودة والبلاغات ونشر تعديل مراجع   |
| مدير نظام    | المستخدمون والأدوار وكلمات المرور والصحة؛ لا يراجع أو ينشر تلقائيًا  |

النظام يطبق خمس سياسات فصل واجبات: مراجعة المصدر المستورد، اعتماد التشريع، نشر التشريع، مراجعة التعديل، ونشر التعديل. تدار كل سياسة من تبويب مستقل في **إعدادات المنصة ← سياسات وضوابط سير العمل**. يحتوي التبويب على حالة السياسة وخيارات المستخدمين المستثنين وسبب التغيير. شاشة المستخدمين تعرض الاستثناءات أمام اسم المستخدم فقط ولا تمنحها أو تلغيها. لا تمنح الاستثناءات الدور المطلوب للعملية، وتغييرها يبطل جلسات المستخدمين المتأثرين.

## دورة المحتوى

1. ينشئ مدخل البيانات مصدرًا ومسودة في `INBOX` أو `DRAFT`.
2. يكمل البيانات الأساسية والمادة ويذكر سبب كل تغيير، ثم يرسل إلى `IN_REVIEW`.
3. يقبل مراجع مستقل إلى `APPROVED_FOR_PUBLISHING` أو يعيدها إلى `DRAFT` بسبب مسجل.
4. ينشر مدير محتوى مستقل؛ تتحقق الخدمة من المصدر والحقول الأساسية ومراجعة OCR والتعارض الزمني داخل معاملة.
5. الأرشفة لا تحذف النص المنشور، بل تغير حالة سير العمل وتبقي التاريخ والتدقيق.

## أقسام اللوحة

- **لوحة التحكم:** المقاييس، جودة المحتوى، حالات الطابور ونبض العامل.
- **الاستيراد:** الرفع، حالة الاستخراج، المعاينة جنب المصدر، مراجعة OCR وإنشاء المسودة.
- **المحتوى:** التصفية حسب الحالة، تحرير المسودة، موادها، مصادرها وسجل انتقالاتها.
- **بيانات التشريع:** العنوان والملخص والرقم والسنة ورمز العرض والتواريخ والنوع والجهة والحالة القانونية والتحقق والموضوعات، وبيانات عدد الجريدة وتاريخها وناشرها وملاحظاتها. كما تدار المواد ووسمها المنشور وترتيبها وربطها البنيوي، والأبواب والفصول، والمصادر، والملحقات والعلاقات.
- **التعديلات:** تعرض القائمة كل وثيقة في صف مختصر. يفتح العنوان أو زر **عرض** صفحة التفاصيل التي تفصل بين بيانات الوثيقة وعناصرها المرتبة. تنفذ المراجعة والنشر من صفحة التفاصيل، بينما يفتح زر **تعديل** نموذج المسودة داخل الصفحة نفسها. تدعم العناصر عمليات `ADD/REPLACE/DELETE/REPEAL/RENUMBER/CORRECT` ثم تطبق زمنيًا عند نشر الوثيقة.
- **الجودة:** مصدر أو نفاذ مفقود، OCR غير مراجع، تعديل غير مربوط، تعارض أو رابط مكسور، مع قرار حل موثق.
- **البلاغات:** فتح البلاغ وتغيير حالته وتسجيل الإجراء.
- **القواميس:** مسودة إصدار مرادفات، إضافة أو حذف، ثم تنشيط إصدار واحد.
- **المستخدمون:** إنشاء، تفعيل/تعطيل، أدوار، عرض استثناءات السياسات أمام الاسم، وإعادة تعيين كلمة المرور.
- **التدقيق:** قيم قبل/بعد والفاعل والسبب والوقت؛ لا يوجد زر حذف أو تعديل.
- **القوائم المرجعية:** أنواع التشريعات والجهات والموضوعات وتفعيلها وترتيبها الأبوي؛ وهي مصدر قوائم الإدخال والفلاتر.
- **إعدادات المنصة:** الاسم والهوية والشعار النصي أو رابط أصل محلي/HTTPS، الألوان والتدرج والخلفية والزخرفة وحجم النص القانوني، وخمسة تبويبات لسياسات سير العمل مع التعطيل العام واستثناءات المستخدمين، وأدوات الترويسة وروابطها والتذييل وأسماء تبويبات التشريع.
- **الصفحات العامة:** الدستور والمنظومة والسياسات والأخبار والتعريف والتواصل والشروط والخصوصية؛ لكل صفحة مقدمة وأقسام وحالة نشر.

الأعداد الظاهرة مثل عدد المواد والتعديلات واللوائح لا تحرر يدويًا؛ تتغير فور إضافة/تعديل السجلات التابعة الصحيحة. هذا يمنع اختلاف العدد الظاهر عن المحتوى الفعلي.

## تعديلات المواد

لا يحرر النص المنشور مباشرة. مشروع التعديل يحدد أداة مصدر مراجعة، المادة أو محدد الفقرة، العملية، تاريخ الأثر وترتيب التطبيق. عند النشر تقفل المعاملة المادة ونسخها، تغلق الفترة السابقة، تنشئ نسخة جديدة و`ArticleModification` و`PreviousTextSnapshot` وسجل تدقيق، ثم تطلب إعادة الفهرسة. `DELETE` و`REPEAL` ينشئان نسخة ملغاة فارغة، و`RENUMBER` يتطلب الوسم الجديد.

في المسودة، يحفظ نموذج المادة النص والوسم الحالي والوسم كما نشر ومفتاح الترتيب والباب/الفصل وتاريخ بداية النفاذ داخل معاملة واحدة. بعد النشر تستخدم صفحة عمليات التعديل بدل تغيير المادة مباشرة.

## إجراءات التشغيل

- افحص `/api/v1/health` قبل النشر؛ `worker=stale` يعني أن مهام الاستيراد والفهرسة لا تتقدم.
- نفذ `npm run backup` قبل ترحيل أو إصدار كبير و`npm run restore:check` دوريًا.
- راقب `journalctl -u yemen-legislation-api` و`journalctl -u yemen-legislation-worker`.
- شغّل `npm run reindex` عند إصلاح بيانات المصدر أو استعادة قاعدة؛ الفهرس ليس أصلًا مستقلًا.
