# معمارية واجهة الإدارة

## الحالة السابقة

كانت روابط الإدارة معروضة في مستوى واحد داخل الشريط الجانبي، وكانت إعدادات المنصة وبيانات التشريع تُعرض كأقسام طويلة في صفحة واحدة. لم تكن حالة فروع التنقل محفوظة، ولم تكن التبويبات ممثلة في URL. اعتمد إظهار معظم الواجهات على أسماء الأدوار بدل العملية الدقيقة، وكانت صفحات المستخدمين تخلط إنشاء الحساب وإدارة الأدوار والحالة في جدول واحد.

## المشكلات التي عولجت

- غياب التسلسل الهرمي والسياق النشط في التنقل.
- صفحات طويلة يصعب حفظ قسم محدد منها أو مشاركة رابطه.
- عدم وجود شاشة مستقلة للأدوار أو تفسير للصلاحيات الفعالة.
- عدم التمييز بين الصلاحية الموروثة والمنح أو الرفض المباشر.
- إظهار بعض أدوات التعديل لمن يملك العرض فقط، مع اعتماد الرفض على الخادم لاحقًا.
- حالات فارغة وتحميل وأخطاء غير موحدة، وجداول واسعة على الهاتف.

## شجرة التنقل الجديدة

```text
لوحة المؤشرات
├── إدارة المحتوى
│   ├── التشريعات
│   ├── الاستيراد والمصادر
│   ├── التعديلات
│   ├── أنواع التشريعات
│   ├── التصنيفات والموضوعات
│   └── الجهات
├── إدارة البحث
│   └── قاموس البحث
├── المستخدمون والوصول
│   ├── المستخدمون
│   ├── الأدوار
│   └── الصلاحيات
├── إعدادات المنصة
│   ├── عام
│   ├── الهوية والمظهر
│   ├── التنقل
│   ├── صفحة التشريع
│   ├── سياسات سير العمل
│   └── الصفحات العامة
└── النظام والحوكمة
    ├── جودة البيانات
    ├── بلاغات المحتوى
    └── سجل التدقيق
```

لا يُعرض الفرع أو العنصر إلا إذا كانت للمستخدم صلاحية الوصول المقابلة. يُفتح الفرع النشط تلقائيًا، وتحفظ حالة الفروع وتصغير الشريط في `localStorage`. تتحول الشجرة إلى drawer مستقل على الهاتف مع زر إغلاق داخل اللوحة وطبقة حجب.

## جرد الصفحات وتقسيمها

| الصفحة            | النوع         | التنظيم الجديد                                                     |
| ----------------- | ------------- | ------------------------------------------------------------------ |
| لوحة المؤشرات     | ملخص تشغيلي   | بطاقات مؤشرات وأقسام مستقلة                                        |
| التشريعات         | قائمة         | بحث، حالة، ترقيم صفحات، انتقال للتفاصيل                            |
| تفاصيل التشريع    | كيان معقد     | بيانات عامة، مواد، بنية، ملاحق، علاقات، مصادر، سير عمل             |
| الاستيراد         | قائمة + إنشاء | تبويبا قائمة الانتظار ورفع مصدر                                    |
| التعديلات         | قائمة + إنشاء | تبويبا سجل التعديلات وإنشاء تعديل                                  |
| البيانات المرجعية | master list   | مسار وتبويب مستقل للأنواع والموضوعات والجهات                       |
| قاموس البحث       | قائمة إصدارات | إنشاء مشروط بالصلاحية وقائمة النسخ والمفردات                       |
| المستخدمون        | قائمة         | بحث، حالة، دور، pagination، تحديد وإجراءات جماعية                  |
| تفاصيل المستخدم   | كيان أمني     | ملف، أدوار، صلاحيات مباشرة، فعالة، نشاط، جلسات                     |
| الأدوار           | قائمة         | بحث، مؤشرات العدد، إنشاء دور مخصص                                  |
| تفاصيل الدور      | كيان أمني     | عام، صلاحيات، مستخدمون، سجل تغييرات                                |
| الصلاحيات         | مستكشف تحليلي | مصفوفة، موارد، أدوار، صلاحيات حساسة                                |
| إعدادات المنصة    | إعدادات       | مسار مستقل لكل تبويب وحفظ مستقل لكل مجموعة                         |
| سياسات سير العمل  | سياسات        | تبويب لكل سياسة، تعطيل عالمي واستثناءات المستخدمين في الصفحة نفسها |
| الجودة والبلاغات  | قوائم تشغيلية | أدوات المعالجة مخفية عند صلاحية العرض فقط                          |
| سجل التدقيق       | قائمة زمنية   | فلتر عملية، pagination، تفاصيل قبل/بعد قابلة للطي                  |

## المكونات المشتركة

- `AdminLayout`, `AdminPageHeader`, `AdminTabs`.
- `PermissionExplorer` ويُستخدم للدور والمستخدم والعرض الفعلي والكتالوج.
- `UnsavedChangesGuard` لحماية النماذج ذات التعديلات غير المحفوظة.
- مكونات الحالة الحالية: `LoadingCards`, `ErrorPanel`, `StatusBadge`.

جميع التبويبات الرئيسية ممثلة في المسار؛ لذلك يعمل النسخ والتحديث وأزرار السابق/التالي. الحفظ مستقل لكل مجموعة إعدادات، مع سبب إلزامي وسجل تدقيق وتعطيل زر الحفظ عند عدم وجود تعديل.
